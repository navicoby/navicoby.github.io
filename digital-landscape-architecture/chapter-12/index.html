1단위. 모형에 관측과 상태를 연결하기

12.1 디지털트윈은 어떤 업무를 위해 필요한가

준공 모형에 수목이 표시되어 있어도 최근에 전정했는지, 토양이 얼마나 젖어 있는지, 고장 신고가 처리되었는지는 알 수 없다. 유지관리에서 필요한 것은 과거의 설계 형상뿐 아니라 지금까지의 관측·작업·확인 기록이다. 이 기록이 객체와 연결되어야 다음 관리를 판단할 수 있다.

이 책에서 **디지털트윈(digital twin)**은 실제 대상의 디지털 표현을 관측·이력과 연결해 정한 업무에 맞게 상태를 갱신하고 판단에 사용하는 체계로 다룬다. 기술 분야마다 정의와 구현 범위가 다르므로 ‘디지털트윈’이라는 이름과 함께 대상, 갱신 주기, 연결 자료, 가능한 판단을 명시한다. 정교한 3D 화면은 이 체계의 한 부분이 될 수 있지만 관측과 관리의 연결을 대신하지 않는다.

**자산(asset)**은 지속적으로 식별하고 관리할 대상이다. **상태(state)**는 정한 시점에서 그 대상을 설명하는 값이나 범주다. 설계 규격, 관측값, 관리자가 확인한 상태, 모델 예측을 한 열에 덮어쓰면 어떤 값인지 알 수 없다. 수목의 계획 수고와 최근 측정 수고를 나누고, 측정하지 않은 경우에는 최근 상태의 확인 시점을 함께 표시한다.

기존의 시설 대장과 작업일지는 이미 자산 이력을 관리해 왔다. 디지털트윈은 그 기록을 공간·센서·모형과 연결하고 갱신 과정을 반복 가능하게 만든다. 모든 항목을 실시간으로 갱신할 필요는 없다. 관수 판단의 토양 수분과 연간 수목 규격 조사의 갱신 주기는 달라도 된다. 목적에 필요한 시점에 충분한 품질로 정보를 얻는 것이 기준이다.

12.2 데이터가 들어오는 구조

입력은 센서의 연속 값, 정기 촬영, 현장 조사, 민원과 작업 기록으로 나눌 수 있다. 각 자료에는 대상 ID, 관측 항목, 시점, 위치·설치 조건, 단위와 품질이 필요하다. 관측 시점과 서버에 도착한 시각은 다를 수 있다. 통신이 끊겼다가 지난 기록이 한꺼번에 들어와도 이를 현재 관측으로 바꾸지 않는다. 과거 관측은 이력에 추가하되, 현재 상태를 갱신할지는 관측 시각과 품질에 따른 별도 규칙으로 결정한다.

OGC SensorThings API는 서로 다른 센서 시스템의 관측과 메타데이터를 관리·조회하는 표준적 연결 방법을 제공한다. 이 책에서는 특정 제품을 반드시 도입하라는 뜻보다 센서·관측·대상·속성을 구별해 교환하는 구조를 배운다. OGC: SensorThings API

W3C의 SOSA/SSN은 관측, 센서, 관측 속성과 대상 등을 의미적으로 표현한다. 관측 대상에 해당하는 시각과 결과가 만들어진 시각을 구분할 수 있다. 8장의 지식그래프와 연결할 때도 센서의 이름만 저장하기보다 무엇을 관측한 결과인지 남긴다. W3C: SOSA/SSN

자료 수신 단계에서는 형식과 범위를 확인하고, 분석 단계에서는 관측의 의미와 품질을 검토하며, 상태 갱신 단계에서는 채택 규칙을 적용한다. 실패한 센서의 마지막 값을 화면에 계속 보여줄 수는 있지만, 새 값처럼 표시하지 않도록 마지막 유효 관측 시각과 만료 상태를 함께 보여준다.

과거 기록의 정정도 원본을 지우고 숫자만 바꾸는 방식보다 정정한 기록과 이유를 연결하는 방식이 추적에 유리하다. 그러면 ‘그때 현장에서 무엇을 관측했는가’와 ‘그때 시스템은 어떤 자료를 알고 판단했는가’를 구별할 수 있다. 뒤늦게 확보한 좋은 관측으로 과거 분석을 다시 계산할 수는 있지만, 당시 작업자가 그 정보를 이미 알고 있었다고 기록하지는 않는다.

2단위. 관측을 관리 작업과 확인으로 연결하기

12.3 관측 사건과 상태 전이

토양 수분 값이 정한 범위를 벗어나면 시스템은 관수 후보를 만들 수 있다. 그 값이 센서 고장인지 실제 건조 상태인지 확인하지 않고 작업 완료 상태로 바꿀 수는 없다. **상태 전이(state transition)**는 어떤 사건과 조건에 따라 기록의 상태가 바뀌는 규칙이다. 관측 수신, 확인 필요, 작업 계획, 실행 기록, 검측, 상태 갱신을 구분하여 정의할 수 있다.

공통 공원의 초본 식재지에서 상태 변화를 설명해 보자. 센서나 조사에서 건조 의심 기록이 들어오면 해당 식재 구역과 연결한다. 담당자는 센서 품질, 강우·관수 이력과 현장 상태를 확인한다. 관리가 필요하면 작업지시를 만들고, 실제 작업량과 시각을 기록한다. 이후 관측과 작업 확인을 거쳐 해당 작업의 완료 여부를 정한다. 이 예는 실제 관수 처방이나 D03의 관측 결과가 아니다.

자체 상태 흐름. 선은 가능한 기록 전이이며 자동 장비 작동 명령이 아니다.

확인 결과 조치가 필요하지 않다면 그 판단과 근거를 남기고 작업을 만들지 않는다. 같은 관측이 재전송되어도 사건 ID로 중복을 확인하여 동일한 작업지시를 여러 번 생성하지 않도록 한다.

‘장비가 명령을 받음’, ‘작업을 수행했다고 보고함’, ‘정한 완료 조건을 확인함’은 다른 사건이다. 관수 밸브를 열었다는 신호만으로 필요한 물이 대상 구역에 전달되었다고 확정하지 않는다. 3장의 검측 개념이 운영 단계에서도 계속 필요한 이유다.

12.4 수목·토양·시설의 시간은 다르다

관리 자료를 모두 같은 간격으로 해석하지 않는다. 토양 수분은 기상과 관수에 따라 빠르게 달라지고, 수목 규격의 변화는 더 긴 기간에 걸쳐 평가할 수 있다. 전정은 짧은 작업이지만 이후 수관 형상과 관측 조건을 크게 바꿀 수 있다. 변화 분석에서 관리 사건을 함께 읽으면 자연적 생장과 인위적 변경을 혼동할 가능성을 줄일 수 있다.

**시계열(time series)**은 시점 순서로 연결한 관측 값이다. 측정 간격이 불규칙하거나 결측이 있을 수 있으며, 보간한 값은 실제 측정과 구별한다. 갑작스러운 값의 변화가 실제 상태인지 센서 교체·재보정인지 확인할 수 있도록 장비 이력을 연결한다.

관리 질문 연결할 자료 기록할 확인 범위
관수가 필요한가 토양 수분·강우·관수 이력 설치 깊이·대표성·센서 품질
수관 변화가 왜 생겼는가 반복 영상·전정·기상 기록 같은 개체·가림·관측 조건

관리가 진행될수록 자료가 쌓이지만, 기록이 많다는 이유만으로 예측 모형을 바로 학습할 수 있는 것은 아니다. 결측과 장비 변경, 관리 개입의 기록이 일관되어야 한다. 사용하지 않는 센서 값을 무한히 수집하기보다 실제 판단에 필요한 항목을 우선하여 관리한다.

3단위. 상태의 갱신에서 미래 반응의 예측으로

12.5 월드모델은 무엇을 예측하는가

**월드모델(world model)**은 환경의 상태나 관측이 행동과 시간에 따라 어떻게 변할지 내부적으로 표현·예측하는 모델을 뜻한다. 이 용어도 연구마다 범위가 다르므로 입력 상태, 행동, 다음 상태와 예측 시간을 함께 설명한다. 복셀을 만들거나 정적인 공원 장면을 렌더링한 것만으로 변화 예측 모델이 완성되는 것은 아니다.

Ha와 Schmidhuber의 연구는 영상을 압축한 표현과 시간에 따른 변화 예측을 결합하여 에이전트의 행동 학습에 사용하는 방법을 제시했다. DreamerV3도 학습한 환경 모델에서 미래 상황을 예측하며 행동을 개선하는 접근이다. 여기서는 방법의 구조만 소개하며 게임·제어 과제의 성능을 수목 생장이나 조경 시공 성능으로 옮기지 않는다. World Models, DreamerV3 원 연구

조경에서 생각할 수 있는 질문은 ‘현재 토양 상태와 기상 조건에서 관수량을 달리하면 다음 상태가 어떻게 달라질까’다. 이 질문에는 상태 관측, 관수 행동, 다음 관측과 시간 간격이 필요하다. 영상만 많이 모아도 작업과 결과의 관계가 없으면 관리 행동의 효과를 학습하기 어렵다. 관수량을 늘린 날이 더 더웠다면 두 요인의 영향을 구별하는 문제도 남는다.

11장의 물리 모형은 정한 방정식과 매개변수로 상태 변화를 계산한다. 학습 모델은 자료에서 입력–출력 관계를 배운다. 두 방식을 함께 쓰는 경우에는 어떤 부분을 물리 계산이, 어떤 부분을 학습이 담당하는지 밝힌다. 학습으로 계산을 빠르게 근사하는 것과 실제 생태 과정을 더 정확하게 설명하는 것은 별도의 성과다.

12.6 예측이 관리에 쓰이기 위한 확인

예측 검증에서는 먼저 단순한 기준을 둔다. 직전 값을 그대로 쓰는 방법, 계절별 평균, 기존의 간단한 물수지와 비교하면 복잡한 모델의 추가 가치를 볼 수 있다. 시간 순서를 지켜 미래 자료를 감춘 상태에서 예측하고, 예측 기간이 길어질 때 오차가 어떻게 변하는지 확인한다.

한 단계 예측이 잘 맞아도 여러 단계를 이어 계산하면 오차가 누적될 수 있다. 모델이 스스로 만든 값을 다음 입력으로 쓰기 때문이다. 새로운 수종·토양·기후 조건으로 이동할 때는 학습 범위 밖인지 확인하고, 불확실성이 큰 조건에서는 관측을 추가하거나 관리 판단을 보류한다.

디지털트윈의 운영과 월드모델의 예측은 서로 연결되지만 같은 것은 아니다. 운영 체계는 어떤 관측과 작업이 실제로 일어났는지 관리한다. 예측 모델은 정한 가정 아래 앞으로 어떻게 될지를 제안한다. 예측한 작업 결과를 실제 완료 기록으로 저장하지 않는다. 예측 시점·모델 버전·입력 상태·적용한 행동 가정을 따로 남긴다.

현재 책의 공통 공원에는 장기 센서 자료와 관리 효과의 정답이 없다. 따라서 이 장은 데이터 연결과 관리·예측 구조의 초고이며, 실제 디지털트윈 운영이나 월드모델 학습 결과를 제시하지 않는다. 다음 13장은 이렇게 정리한 공간·상태·작업 정보를 이동 장비와 로봇이 사용할 수 있도록 바꾸는 방법을 다룬다.
