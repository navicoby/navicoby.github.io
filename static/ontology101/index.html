개념과 관계를 설계하는 첫걸음

서로 다른 사람이 같은 데이터를 같은 뜻으로 읽으려면 무엇을 정해야 할까. Noy와 McGuinness의 입문서에서 온톨로지 설계의 출발점을 살펴본다.

Natalya F. Noy · Deborah L. McGuinness

01 / 핵심 개념

이름에 뜻과 관계를 부여한다

온톨로지는 한 분야의 개념과 그 사이의 관계를 명시한 지식의 틀이다. 용어의 의미와 전제를 드러내면 사람과 프로그램이 지식을 공유하고 재사용하기 쉬워진다.

클래스 Class
어떤 종류의 대상을 다루는지 정한다.
속성·관계 Slot / Property
대상의 특성과 다른 대상과의 연결을 기술한다.
제약 Facet
값의 형식, 허용 범위와 개수를 정한다.
개체 Instance
정의한 개념에 속하는 구체적인 사례다.

내용 근거: 원문 1–4쪽

02 / 개발 흐름

답하고 싶은 질문부터 정한다

  1. 목적과 범위를 정한다. 누가 사용하며 어떤 질문에 답해야 하는지 적는다.
  2. 기존 모델을 살피고 용어를 모은다. 재사용할 정의가 있는지 확인한다.
  3. 개념·관계·제약을 함께 설계한다. 분류 체계와 속성을 오가며 다듬는다.
  4. 사례를 넣고 검토한다. 처음의 질문에 답할 수 있는지 확인하며 수정한다.

유일한 정답을 찾기보다 목적에 맞는 모델을 만들고, 실제 사용을 통해 계속 고쳐 나가는 것이 중요하다.

원문의 일곱 단계를 네 묶음으로 요약했다. 개발 절차 5–11쪽 · 결론 23쪽

03 / SPATIALFLARE의 적용 해설

소공원 데이터에 대입해 보면

교목의 수량만 저장하는 데서 한 걸음 더 나아가, 각 나무가 어떤 대상이고 어디에 식재되는지 일관된 뜻으로 표현할 수 있다.

구분간단한 예시
클래스식물의 한 유형인 교목
개체설계도에 배치된 교목-001
속성교목-001의 수고: 4m
관계교목-001의 식재 위치: 식재구역 A

이때 ‘교목은 식물의 한 유형’이라는 분류와 ‘교목이 공원에 속한다’는 구성 관계를 구별해야 한다. 이런 의미 체계는 배치 좌표나 공정 계산과 연결할 수 있지만, 그 계산 자체를 대신하지는 않는다.

이 예시와 적용 의견은 SpatialFlare가 작성했다. 원문에는 와인 분야의 예시가 사용된다. 유형 관계의 설명은 원문 12–13쪽을 참고했다.

출처와 읽는 범위

Noy, N. F., & McGuinness, D. L. (2001). Ontology Development 101: A Guide to Creating Your First Ontology. Stanford University, KSL Technical Report KSL-01-05. 공식 서지 안내.

원문은 당시 Protégé-2000의 프레임 기반 모델을 사용한다. 이 글은 개념 설계의 입문 원칙을 다루며, 최신 OWL 구현 지침을 설명하는 글은 아니다.
