# 집필·수정 규칙

## 장의 계약

프로젝트 스킬 `.agents/skills/navicoby-geospatial-author/SKILL.md`를 먼저 읽습니다. 목적은 “좌표 있는 데이터 → 도시·조경 분석 → GeoAI/Spatial AI”이며 도구 나열식 강의를 피합니다. 한 장에는 하나의 공간 질문, 검산 가능한 결과, 실제 자료로 바꾸는 방법과 해석 한계를 넣습니다.

기본 순서: 목표·선수·시간·자료·환경 → 개념 → 왜 필요한가 → 핵심 API → 최소 실행 예제 → 실무 예제 → 시각화 → 흔한 오류 → 연습문제 → 다음 단계 → 출처.

## 파일 편집

1. `pages/`의 Markdown을 수정합니다. 신규 장은 `curriculum.json`, 보조 안내는 `pages.json`에 등록합니다.
2. 코드는 `examples/`를 원본으로 관리합니다. 본문에 `{{code:file.py#region}}`를 넣으면 빌더가 `# start:region`과 `# end:region` 사이를 가져옵니다. 최소 예제에 필요한 import와 호출문을 반드시 포함합니다.
3. 환경 파일을 갱신할 때는 공식 안정 문서와 실제 설치·실행 결과를 비교합니다. 검색 결과의 버전 문구를 그대로 “검증 버전”으로 쓰지 않습니다.
4. 가상 자료는 지도·caption·출력에 표시합니다. 실제 공공 자료는 source URL, 취득일, 자료기준일, CRS, 단위, license, 가공 과정을 manifest로 기록합니다.
5. `build.py`로 HTML을 다시 만들고 원본과 생성물을 같은 변경에 포함합니다. 생성 HTML만 직접 고치면 다음 빌드에서 사라집니다.

## 분석 검토

- 벡터: 면적·거리 단위, geometry 유효성, 경계 포함, 다중 매칭·nearest 동률과 결측.
- DEM: 수평/수직 단위, transform 회전, 행 방향, NoData 주변, 경계, degree/percent, flat aspect.
- 위성: 플랫폼과 처리레벨, 촬영일, scale/offset, SCL, 정렬, 혼합픽셀, 유효비율.
- 네트워크: 분석 범위 바깥 우회 경로, 출입구·노드 스냅 거리, 단절, edge weight, 접근 태그.
- GeoAI: 공간·시점 누수, 타깃 dtype/shape, NoData ID, 클래스별 평가와 현장 검증.

설계 임계값은 법규·논문·실측 근거를 제시하거나 “교육용 가정”으로 표시합니다. 높이 미상과 0m, NoData와 부적합, 위성지수와 생육 건강을 혼동하지 않습니다.

## 문장·그림·모바일

한국어 설명체를 유지하고 처음 나오는 전문어만 한국어/영문을 병기합니다. 같은 단위·소수점·색 범위를 일관되게 사용합니다. 개념도는 직접 만든 SVG나 검증된 Mermaid를, 결과 그림은 실제 실행 출력을 사용합니다. 긴 표·코드는 독립 스크롤과 줄바꿈을 제공하고 지도에는 정적 대안을 둡니다. 자세한 점검은 스킬의 `references/mobile.md`를 따릅니다.

## 출처 검토

공식 문서, 데이터 제공기관 상세 페이지, 원 논문을 우선합니다. 주장의 가까이에 직접 링크를 두고 확인일을 기록합니다. 오래된 자료기준일을 웹페이지 수정일로 바꿔 쓰지 않습니다. 접근 실패·파일 미취득·미실행은 해당 범위에 명시합니다. 포털 전체에 하나의 라이선스가 적용된다고 쓰지 않습니다. 비밀키와 개인 자료를 공개 예제에 넣지 않습니다.

## 게시 전 확인

README의 예제 실행·분석 검산·빌드·두 링크 검사 명령을 수행합니다. 320/375/768/1280px에서 가로 넘침, 목차, 코드, 표, 지도 열기, 이미지 대체 텍스트와 키보드 focus를 확인합니다. 계산을 바꾸지 않은 오탈자 수정에 분석 전체를 반복할 필요는 없지만 생성 HTML·링크는 다시 확인합니다.

전체 계획 장을 완성 상태로 표시하지 않습니다. QA.md에 실제 확인한 환경·결과·제한을 남깁니다. 게시 요청이 있는 변경만 원격 사이트에 반영합니다. 최신 main을 먼저 확인하고 기존 콘텐츠의 메인 링크를 보존합니다.

## 목차와 설명의 일치

부·장 등록은 curriculum.json, 보조 안내는 pages.json을 수정합니다. 모든 장에는 라이브러리의 뜻·입력·출력과 실행 예제가 있어야 합니다. 도구 이름만 나열하거나 계획 문장을 본문처럼 게시하지 않습니다. 새 장 추가 시 연속 번호·기존 URL·이전/다음 연결을 검사합니다.

마감 전 오프라인 예제 실행, 단위 검증, Hugo/링크 검사, 데스크톱·모바일 화면 검사를 수행합니다. 게시 뒤 공개 주소에서도 전체 페이지와 링크를 다시 확인합니다.
