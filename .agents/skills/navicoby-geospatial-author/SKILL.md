# 파이썬 공간데이터 사이언스 집필 스킬

## 목적과 독자

실무 조경·도시계획 독자가 Python geospatial foundation → urban/landscape analysis → GeoAI/Spatial AI로 진행하도록 돕는다. GIS 초급자에게는 좌표·단위·자료구조를, 설계 실무자에게는 분석 결과가 의사결정을 바꾸는 이유를 설명한다. Python의 변수·함수·배열 기본은 선수 지식으로 두고 필요한 부분만 짧게 복습한다.

정식 제목은 **파이썬 공간데이터 사이언스 — GeoPandas에서 Spatial AI까지**. Sentinel-2A를 포함한 Sentinel-2 위성영상, 한국 공공데이터, OSM, BIM 연계를 기본 범위에 포함한다. 특정 위성의 현재 운영 상태·재방문 주기를 기억에 의존해 단정하지 않는다.

## 사이트에 맞추기

작업 시작 시 현재 저장소의 `AGENTS.md`, `README.md`, `hugo.toml`, `layouts/index.html`, `.github/workflows/`와 해당 콘텐츠를 읽는다. 조사 당시(2026-09-30) Hugo + PaperMod이며, 독립 학습서는 `static/<route>/index.html`을 메인에 연결하는 방식이었다. 이후 구조가 바뀌면 현재 저장소를 우선한다.

이 프로젝트의 집필 원본은 `books/python-geospatial/pages/`, 실행 예제는 `books/python-geospatial/examples/`, 빌더는 `scripts/geospatial/build.py`, 발행 경로는 `static/python-geospatial/`이다. 공통 스타일은 기존 사이트의 연녹색 바탕·진녹색 링크·절제된 타이포그래피를 따른다. 새 장은 pages 목록에 넣고 공통 탐색에 표시한다. 기존 사이트의 다른 경로, 테마, 배포 설정을 불필요하게 바꾸지 않는다.

스킬 폴더만 전달받았다면 아래 references로 집필 규칙을 확인한다. 저장소가 없으면 원본 구조를 보존한 적용 파일 묶음을 만든 뒤 미적용 상태를 정확하게 알린다. 사용자가 사이트 연결·배포를 요청했다면 검증된 결과를 그 범위에서 반영한다. 요청하지 않은 공유·게시를 이 스킬 자체로 승인하지 않는다.

## 새 장을 만드는 순서

1. 요청한 주제와 전체 `roadmap.md`의 선수·후속 장을 연결한다. 누락된 사소한 선택은 합리적으로 정하고 기록한다.
2. 해당 라이브러리의 공식 안정 문서·릴리스와 데이터 제공기관의 상세 페이지를 확인한다. 검색 요약만으로 API나 라이선스를 확정하지 않는다. 참조한 날짜와 실제 실행 버전을 구분한다.
3. [챕터 템플릿](references/chapter-template.md)으로 개념 → 왜 필요한가 → 핵심 API → 최소 실행 예제 → 조경/도시 실무 예제 → 시각화 → 흔한 오류 → 연습문제 → 다음 단계를 구성한다. 앞에 목표·선수 지식·시간·데이터·환경, 뒤에 출처를 둔다.
4. 네트워크 없이 재현되는 작은 예제를 먼저 작성한다. 실제 데이터를 다루는 확장은 별도로 제공한다. 가상 자료는 제목·그림·설명에 가상이라고 명시한다.
5. 실행 파일을 실행해 결과를 확인하고 코드·본문·그림을 맞춘다. 미실행 예제는 실행됐다고 말하지 않는다. 본문 코드에 `{{code:filename.py}}`를 쓰면 빌더가 실행 원본을 그대로 넣는다. 긴 파일은 주요 단계만 본문에 설명하고 전체 파일 다운로드를 제공한다.
6. 빌더와 링크 검사를 실행하고 Hugo를 빌드한다. `scripts/check_static_navigation.py --public public`을 통과시킨다. [모바일 가이드](references/mobile.md)에 따라 코드·표·지도와 실제 모바일 폭을 확인한다.
7. 완성 장, 실행 조건, 출처, 확인 결과, 적용/게시 상태를 간결하게 보고한다. 전체 목차만 작성한 장을 완성 장으로 표시하지 않는다.

## 문체와 교육 원칙

한국어 설명체(~합니다/~입니다), API·변수·파일 이름은 원어를 쓴다. 처음에는 한국어 뜻과 영문을 병기한다. 도구를 나열하기보다 “이 질문에 이 연산이 필요한 이유”를 설명한다. 한 절에 하나의 핵심 판단을 둔다. 과장된 성능 주장과 AI가 자동으로 설계를 완성한다는 표현을 피한다.

공통 사례는 2,000~4,000㎡ 가상공원, 건물-도로-녹지 관계, 공원 접근성, 보행권, 후보지 평가다. 점·선·면, 속성표, 래스터 배열, 그래프, 텐서의 표현 차이를 계속 연결한다. 편집용 지도·분석용 좌표·실세계 자료의 역할을 구별한다.

## 기술·코드 원칙

- Python, GeoPandas/Shapely 2, pyogrio, pyarrow, Rasterio, NumPy, Matplotlib, Folium, NetworkX/OSMnx를 기초로 한다. GeoAI 장에서만 PyTorch·scikit-image와 필요한 선택 의존성을 더한다. 실제 검증 버전은 환경 파일에 고정한다. 문서의 `latest`에 rc/dev가 있으면 안정 릴리스와 혼동하지 않는다.
- `sjoin(predicate=...)`, `sjoin_nearest(distance_col=..., max_distance=...)`, `union_all()`, OSMnx 2의 문서화된 API를 사용한다. 폐기된 `op=`, 오래된 `geopandas.datasets`, PyGEOS 중심 예제를 새로 만들지 않는다.
- CRS 메타데이터 지정 `set_crs`와 좌표 변환 `to_crs`를 구별한다. 미상 CRS를 추측해 덮어쓰지 않는다. 거리·면적은 대상지와 단위에 맞는 투영 CRS에서 계산한다. EPSG:5179를 한국의 모든 원자료 좌표계라고 단정하지 않는다. 웹 표시는 EPSG:4326으로 변환한다.
- sjoin의 다중 매칭·경계 술어·nearest 동률·미매칭을 설명한다. geometry 유효성·빈 geometry·중복 ID를 점검하고 임의의 `buffer(0)`로 조용히 고치지 않는다. 건물 중심점과 footprint 기준 결과를 구별한다.
- 래스터는 CRS, transform, 해상도, band, dtype, NoData, 수직 단위를 기록한다. DEM의 경사도(degree/percent), 향의 북쪽 기준, 행 방향의 부호를 설명한다. 회전 격자·위경도 DEM은 예제 지원 범위를 확인하고 필요하면 재투영한다. 이웃 연산에서 NoData를 전파하고 경계를 처리한다.
- Sentinel-2는 L1C/TOA와 L2A/SR(BOA), 밴드별 해상도, SCL/품질마스크, 반사도 scale/offset, 획득일·처리 baseline을 기록한다. 클래스 마스크는 nearest, 연속값은 목적에 맞는 보간을 선택한다. 같은 CRS만으로 격자 정렬이 끝났다고 하지 않는다. harmonized 자료에 offset을 중복 적용하지 않는다.
- 3,000㎡ 공원은 10m 격자 약 30셀의 면적이다. Sentinel-2로 개별 수목·식재 위치를 정밀 판정하지 않는다. 주변 녹지·시계열에는 위성영상, 공원 내부에는 더 높은 해상도의 허용된 자료를 쓴다.
- CNN/U-Net 입력은 N,C,H,W, 타깃은 클래스 ID/NoData를 분리한다. 훈련/검증/시험은 공간과 시점 단위로 분할하고 정규화 통계는 훈련 자료로만 산출한다. IoU/F1·클래스 불균형·라벨 불확실성을 기록한다. NDVI를 수종·건강·온도 정답으로 취급하지 않는다.
- BIM 연계는 IFC 객체 ID, GIS 위치, 길이 단위, 높이 datum, `IfcMapConversion` 등 지리참조를 먼저 맞춘다. 2D footprint를 BIM 전체 의미정보와 동일시하지 않는다.

## 자료와 출처

[자료·검증 원칙](references/sources.md)을 적용한다. 공식 API·명세·원 논문을 우선하고 문서 제목, 제공기관/저자, 직접 URL, 확인일을 기록한다. 수치·API 주장의 가까이에 링크를 두고 장말 목록을 보완한다. 직접 인용보다 독자적인 설명을 쓴다.

공공데이터도 자료별 이용조건이 다르다. 데이터 상세 URL, 다운로드일, 촬영/기준일, 포맷, CRS/수직 기준, 해상도, 라이선스, 가공 내역을 manifest에 남긴다. 열람과 원본 재배포를 구별한다. 인증키·토큰은 정적 HTML·코드·저장소에 넣지 않는다. 공식 페이지 접근 불가·이용조건 미확인은 그대로 표시하고 검증된 대체 경로를 제시한다.

## 시각화와 출판

SVG 개념도와 실제 계산으로 만든 도표를 우선한다. Mermaid는 사이트에 렌더러가 검증된 경우만 사용하며 SVG/텍스트 대안을 둔다. 그림에 변수·단위·범례·가상/실측 구분을 붙인다. 면적이 다른 구역은 원시 건수와 밀도 지도를 구별한다. Folium HeatMap의 화면 커널을 분석용 KDE로 해석하지 않는다.

지도에는 CRS(분석), 축척·분류 기준, 데이터 제공자와 배경지도 attribution을 표시한다. 인터랙티브 지도는 명시적 열기, 제목 있는 iframe, 정적 대안, 전체 화면 링크를 제공한다. 큰 원본 GeoTIFF와 위성영상은 GitHub Pages에 싣지 않고 작은 결과·허용된 파생물·취득 방법을 싣는다.
